# scb-pack

SealedCodeBounty challenge packager (`docs/BUILD_PLAN_v2.md` §4.2/§4.5).

```bash
npm install && npm run build
node dist/index.js <challenge-dir> --out out/ [options]
```

| Option | Default | Meaning |
|---|---|---|
| `--name` | dir slug | challenge name (lowercase `[a-z0-9-]`) |
| `--kind` | `tcp_service` | `tcp_service` \| `binary` |
| `--port` | 1337 | tcp_service listen port (manifest + compose expose) |
| `--exec` / `--arg` | — | binary kind: executable path / repeatable argv token |
| `--timeout-secs` / `--memory-mb` / `--cpus` | 60 / 512 / 1 | verification limits (manifest only at this stage) |
| `--aslr` | off | determinism block; `off` adds the setarch parity wrapper to the dev plane AND is what the verifier will use |
| `--seed` | 0 | exported as `SEED` to the target process |
| `--upload-url` | — | phase-2 storage hook; currently a NotImplemented stub |

Pipeline: `docker build` → static `/flag` check via `docker create`+`cp`
(the image is never executed) → `docker save | gzip` streamed to
`<sha256>.tar.gz` while hashing → `manifest.json` (schema v2) +
`docker-compose.yml` dev plane.

Exit codes: 0 ok · 2 usage · 3 docker missing · 4 flag invalid ·
5 upload not implemented · 6 build failed · 7 save failed.

## scb-submit — hunter submission client

Full §4.3 handshake in one command:

```bash
node dist/scb-submit.js \
  --rpc-url http://127.0.0.1:8899 \
  --keypair ~/.config/solana/hunter.json \
  --bounty <buyer_pubkey>:<numeric_id> \
  --file ./exploit.py \
  --enclave-url http://127.0.0.1:8443 \
  [--blob-url https://... ]      # recorded on-chain (default blob.local placeholder)
  [--program-id Fbqou...]        # defaults to the deployed id
  [--wait]                       # poll until PASS/FAIL
  [--dry-run]                    # print payload shapes; zero network
```

Steps performed (mirroring BUILD_PLAN_v2 §4.3):
1. fetch Bounty → deadline guard client-side
2. fetch Config → enclave X25519 pk
3. `crypto_box_seal(exploit.py, enclave_pk)` — plaintext never leaves the machine unencrypted
4. intent signature over `SCB_SUBMIT_V1 ‖ bounty_pda ‖ sha256(exploit)` with the hunter wallet
5. POST /internal/upload (enclave cross-checks + stores)
6. `submit_exploit(bounty_id, blob_url, sha256)` tx signed by the hunter
7. `--wait` polls status; on FAIL prints resubmit note (redacted log retrieval is a documented TODO)

Cross-language fixture: `test-vectors/intent_v1.json` is generated by
`runner/src/intent.rs :: dump_intent_vector`; `src/test/submit.test.ts`
asserts byte-equality of the TS builder and signature against it.

Tests: `npm test` (builds, runs node:test suite incl. dry-run smoke).
